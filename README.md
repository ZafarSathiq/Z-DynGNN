# Z-DynGNN: Z-score Calibrated Dynamics-Aware Graph Neural Network

**Z-DynGNN** (*Z-score Calibrated Dynamics-Aware Graph Neural Network*) is a computational biology and machine learning framework designed to predict fitness and resistance mutation effects on **New Delhi metallo-$\beta$-lactamase-1 (NDM-1)** with finite-sample, mathematically certified per-residue confidence bounds:

$$|y_i - \hat{\mu}(x_i)| \le B_i \quad \text{with provable coverage } 1 - \alpha$$

## Theoretical Foundation (Correction v1)

Z-DynGNN enforces distribution-free **Topology-Conditioned Conformal Risk Control** (Angelopoulos & Bates; Romano et al.):

1. **Exact Finite-Sample Coverage**: For any target confidence $1 - \alpha$ (e.g. 95%), the prediction interval $\mathcal{C}(x_i) = [\hat{\mu}(x_i) - B_i, \hat{\mu}(x_i) + B_i]$ guarantees marginal coverage $\mathbb{P}(y_i \in \mathcal{C}(x_i)) \ge 1 - \alpha$ without Gaussian assumptions on fitness residuals.
2. **Z-DynGNN Architecture**: Predictions and aleatoric scales are generated by **Z-DynGNN** (*Z-score Calibrated Dynamics-Aware Graph Neural Network*), incorporating directional perturbation dynamics ($\text{DCI}_{\text{asym}}$) and outputting $(\hat{\mu}(x_i), \hat{\sigma}(x_i))$ via Gaussian NLL loss to parameterize studentized Z-score residuals.
3. **Topology Conditioning**: Instead of uniform error bars across the protein, the certificate scales with local structural and dynamic properties:
   $$B_i = \hat{q}_{1-\alpha}\left(\mathcal{S}(i)\right) \cdot \hat{\sigma}(x_i)$$
   where $\mathcal{S}(i)$ discretizes residues by contact coordination number $d_i$ and the Asymmetric Dynamic Coupling Index ($\text{DCI}_{\text{asym}}$).
4. **Strict Position-Disjoint Partitioning (70% Train / 15% Calib / 15% Test)**: Held-out test positions are never exposed during model training or conformal calibration, eliminating spatial data leakage.

*For full mathematical derivations, distribution-free risk control proofs, and complete architecture specifications, see `01. Correction v1 - NDM-1 Strategy.md`, `02. Comprehensive Guide - Original Strategy vs Correction v1 Explained.md`, and `17. System Architecture, Nix Deployment & Complete Scientific Synthesis.md`.*

## Environment Setup & Installation

### Option A: Nix Flake (Recommended)

The project includes declarative Nix manifests ensuring identical C runtime libraries, compiler toolchains, and package versions:

```bash
# 1. Enter the Nix dev environment
nix develop

# 2. Inside the Nix shell, initialize the virtual environment with uv
uv venv --python python3.11 .venv
source .venv/bin/activate
uv pip install torch --index-url https://download.pytorch.org/whl/cpu
uv pip install -e ".[dev]"
```

Inside the shell, Python 3.11, `uv`, Git, curl, and GNU C dynamic libraries are automatically configured.
### Option B: Local Python Virtual Environment

If running outside the Nix dev shell:

```bash
# 1. Create virtual environment
uv venv --python python3.11 .venv

# 2. Activate virtual environment
source .venv/bin/activate

# 3. Install core dependencies
uv pip install -e ".[dev]"
```

*Note for Nix / Linux systems*: PyTorch relies on the GNU C++ runtime (`libstdc++.so.6`). The activation script `.venv/bin/activate` automatically sets `LD_LIBRARY_PATH` to resolve dynamic linker dependencies.
